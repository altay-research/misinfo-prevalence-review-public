Turning on the submission form

So people without a GitHub account can send you a missed study
About eight minutes. Two things are yours, plus four commands; the rest is mine.

What it does when it is on. A reader types into a form on the site. It reaches a small program on Cloudflare, which files it as an issue in a private repository only you can see. Nothing is published, nothing enters the dataset, and nobody needs an account.

Until you do this, the site keeps the GitHub links it has now. They work, but they ask for an account, which is the problem you wanted solved.

1. Cloudflare account DONE

nothing to do

You already have one: the baby shower site runs on it (Cloudflare Pages, project camille-sacha-bebe, at camille-sacha-bebe.pages.dev). The same account covers Workers and Turnstile, both on the free tier. Step 4 signs in to it.

2. A GitHub token YOU

3 minutes · gives me the FIRST string

Go to github.com/settings/personal-access-tokens/new and set exactly these:

Token namemisinfo submissions
Resource owneraltay-research
Expiration1 year
Repository accessOnly select repositories → misinfo-prevalence-submissions
PermissionsRepository permissions → Issues → Read and write. Nothing else.

Generate, then copy the token. GitHub shows it once.

Scoped this way, the worst it can do if it ever leaks is file issues in a private repo that exists to receive them. It cannot touch the review's own repository.

3. A Turnstile widget YOU

2 minutes · gives me the SECOND string

In the Cloudflare dashboard — the same one the baby shower site is in — go to Turnstile → Add widget:

Widget namemisinfo prevalence site
Hostnamealtay-research.github.io
Widget modeManaged

You get two keys. The site key is public and goes in the page; the secret key stays on Cloudflare. Keep both to hand.

This is the invisible check that stops the form becoming a spam faucet. Most people never see anything.

4. Deploy, and set the two secrets YOU

3 minutes · in the terminal

Paste these one at a time. The first opens a browser to connect your Cloudflare account.

cd ~/Desktop/Claude/Random/Misinfo_Prevalence_Review/worker
npx wrangler login
npx wrangler deploy

The last line prints an address ending in .workers.dev. That is the third thing to send me. Then:

npx wrangler secret put GITHUB_TOKEN
npx wrangler secret put TURNSTILE_SECRET

Each asks you to paste a value: the token from step 2, then the secret key from step 3. Neither is ever written to a file.

5. Send me three strings YOU

10 seconds

  • the .workers.dev address from step 4
  • the Turnstile site key from step 3 (the public one, starts 0x4AAA)
  • nothing else — do not send me the token or the secret key, I do not need them and they should not be in a chat log

6. The rest ME

2 minutes

I put the two public values into build_site.py, rebuild the site, run the checks, rebuild the package, pull, and push. The form replaces the GitHub button everywhere, and the GitHub route stays underneath it for people who prefer it. Then I will ask you to try it once from a private browser window so we both see a real submission arrive.

Afterwards

Where submissions arrive

github.com/altay-research/misinfo-prevalence-submissions/issues, or gh issue list -R altay-research/misinfo-prevalence-submissions. Each one is labelled unverified plus missing-study or coding, carries exactly what was typed, and the sender's email if they gave one. You can have GitHub email you on every new issue by watching that repo.

What a submission is

A lead, nothing more. It goes through the same eligibility criteria as everything else or it does not. If one does change the corpus, that is a re-freeze with its own entry in the ledger, like any other change.

If it stops working

Almost always the token expiring, a year out. Re-issue it and run npx wrangler secret put GITHUB_TOKEN again — no redeploy. To switch the form off entirely at any point, tell me and I set one constant back to None; the site returns to GitHub links.

Cost

Nothing. Cloudflare's free tier is 100,000 requests a day.
